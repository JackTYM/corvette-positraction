# Public Share View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user opt in to a public, read-only view of their Collection and Wishlist at `share.corvettepositraction.com/<their-user-id>`.

**Architecture:** One new DB table (`user_settings`) gates four new anonymous-role RLS policies (on `items`, `wishlist_items`, `item_links`, `item_documents`). A new page tree (`app/pages/share/...`) reuses existing display components with all mutation controls stripped, fetching via a new userId-scoped composable that bypasses the existing per-session `useState` caches. Since this app is `ssr:false`, hostname-based routing to that page tree happens client-side via a new Nuxt route middleware (not a server middleware — there's no server-rendered page to redirect at request time).

**Tech Stack:** Nuxt 4 (SPA/`ssr:false`), Neon Data API (PostgREST-compatible) via `@neondatabase/neon-js`, Drizzle ORM + Neon RLS helpers (`drizzle-orm/neon`), Cloudflare Pages (Custom Domains).

**User decisions (already made):**
- Show everything on shared items — no redacted fields (price paid, estimated value included).
- Toggle lives on a new Settings page, linked near "Sign Out" — not a numbered `SEC.` nav tab.
- URL uses the raw user UUID directly: `share.corvettepositraction.com/<uuid>`.
- Documents and Linked Entries are included on shared item detail pages (full parity).
- Share view has real per-item detail pages (grid + detail), not one long page.
- Same Nuxt app/deployment, not a separate minimal deployment — a `share.` Custom Domain routes into the existing app.
- Out of scope: Garage/walls, Diecast Reference, all Add/Edit/Remove flows — the share page tree only ever queries `items` and `wishlist_items` (plus their documents/links).

### Task 1: Database — `user_settings` table, anonymous RLS policies, grants

**Goal:** A user can have a `share_enabled` flag, and when it's true, an unauthenticated Data API request can read (only) that user's `items`, `wishlist_items`, `item_links`, and `item_documents` rows.

**Files:**
- Modify: `db/schema.ts`
- Create: `db/migrations/00XX_*.sql` (auto-generated by drizzle-kit — filename assigned at generate time)
- Create: `db/migrations/00XX_share_grants.sql` (hand-written, custom)

**Acceptance Criteria:**
- [ ] `user_settings` table exists with RLS enabled, readable/writable only by its own owner (authenticated role).
- [ ] `items`, `wishlist_items`, `item_links`, `item_documents` each have a second SELECT policy for the anonymous role, gated on `user_settings.share_enabled`.
- [ ] The anonymous Postgres role has an explicit `GRANT SELECT` on those 4 tables (RLS policies alone are insufficient — every existing table-specific grants migration in this repo, e.g. `db/migrations/0003_item_links_documents_grants.sql`, explicitly `revoke all ... from anonymous` today; this migration is the one place that deliberately reverses that for exactly these 4 tables).
- [ ] Verified against a real (temporary) row: with `share_enabled = true`, an anonymous `curl` request to the Data API can read that user's `items`; with it `false`, the same request returns zero rows.

**Steps:**

- [ ] **Step 1: Add `userSettings` table and the anonymous policies to `db/schema.ts`**

Add the import for `anonymousRole` (confirmed exported by `drizzle-orm/neon` alongside the already-imported `authenticatedRole`):

```ts
import { crudPolicy, authenticatedRole, anonymousRole, authUid } from 'drizzle-orm/neon'
```

Add this table definition (place it near the top, before `items`, since `items`' new policy will reference it):

```ts
export const userSettings = pgTable(
  'user_settings',
  {
    userId: text('user_id').primaryKey().default(sql`auth.user_id()`),
    shareEnabled: boolean('share_enabled').notNull().default(false),
    createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
    updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
  },
  (table) => [
    crudPolicy({
      role: authenticatedRole,
      read: authUid(table.userId),
      modify: authUid(table.userId),
    }),
  ],
).enableRLS()
```

Then add one new policy element to each of `items`, `wishlistItems`, `itemLinks`, `itemDocuments`'s existing policy arrays (alongside their existing `crudPolicy({...})` element — do not remove or modify that one). For `items`:

```ts
export const items = pgTable(
  'items',
  { /* ...unchanged... */ },
  (table) => [
    index('items_user_id_idx').on(table.userId, table.createdAt),
    index('items_source_variant_id_idx').on(table.sourceVariantId),
    check('items_rarity_range', sql`${table.rarity} is null or (${table.rarity} >= 1 and ${table.rarity} <= 3)`),
    crudPolicy({
      role: authenticatedRole,
      read: authUid(table.userId),
      modify: authUid(table.userId),
    }),
    pgPolicy('items_select_shared', {
      for: 'select',
      to: anonymousRole,
      using: sql`exists (select 1 from ${userSettings} where ${userSettings.userId} = ${table.userId} and ${userSettings.shareEnabled} = true)`,
    }),
  ],
).enableRLS()
```

Apply the same `pgPolicy('<table>_select_shared', { for: 'select', to: anonymousRole, using: sql\`exists (select 1 from ${userSettings} where ${userSettings.userId} = ${table.userId} and ${userSettings.shareEnabled} = true)\` })` pattern to `wishlistItems`, `itemLinks`, and `itemDocuments` — same shape every time, just swap the table reference. `itemLinks` and `itemDocuments` already carry their own `userId` column directly (confirmed in the existing schema), so this is a direct check, not a join through `items`.

Name the policies `wishlist_items_select_shared`, `item_links_select_shared`, `item_documents_select_shared` respectively.

### Task 2: `useSharedCollection.ts` — anonymous, userId-scoped reads

**Goal:** A composable that fetches a specific (possibly-not-logged-in-visitor's-target) user's items, wishlist items, links, and documents by explicit `userId` — without touching the existing `useItems()`/`useWishlist()`/etc. composables' global `useState` caches, since those are keyed for "the current session's own data" and would collide or leak if reused here (a logged-in user browsing someone else's share page must never see their own cached `items:list` state bleed into the share view, and vice versa).

**Files:**
- Create: `app/composables/useSharedCollection.ts`

**Acceptance Criteria:**
- [ ] Fetching items/wishlist for a user with sharing disabled returns an empty array (not an error) — this is just what RLS naturally does, don't add a special-case check for it.
- [ ] None of this composable's state is stored under the same `useState` keys as `useItems()` (`items:list`) or `useWishlist()` (`wishlist:list`) — use userId-namespaced keys instead.
- [ ] Reuses the existing row-mapping functions (`fromRow`, `fromLinkRow`, `fromDocumentRow`, `fromWishlistRow`) rather than re-implementing the DB-row-to-domain-object shape.

**Steps:**

- [ ] **Step 1: Write the composable**

```ts
// app/composables/useSharedCollection.ts
import { fromRow, type ItemRow } from '~/composables/useItems'
import { fromLinkRow, otherItemId, type ItemLink, type LinkRow } from '~/composables/useItemLinks'
import { fromDocumentRow, type ItemDocument, type DocumentRow } from '~/composables/useItemDocuments'
import { fromWishlistRow, type WishlistItem, type WishlistItemRow } from '~/composables/useWishlist'
import type { Item } from '~/utils/catalog'

export function useSharedCollection(userId: string) {
  const neon = useNeon()
  const items = useState<Item[]>(`shared:${userId}:items`, () => [])
  const wishlistItems = useState<WishlistItem[]>(`shared:${userId}:wishlist`, () => [])

  async function fetchItems() {
    const { data, error } = await neon.from('items').select('*').eq('user_id', userId).order('created_at', { ascending: false })
    if (error) throw error
    items.value = (data as ItemRow[]).map(fromRow)
  }

  async function fetchWishlistItems() {
    const { data, error } = await neon.from('wishlist_items').select('*').eq('user_id', userId).order('created_at', { ascending: false })
    if (error) throw error
    wishlistItems.value = (data as WishlistItemRow[]).map(fromWishlistRow)
  }

  async function fetchLinksForItem(itemId: string): Promise<ItemLink[]> {
    const [a, b] = await Promise.all([
      neon.from('item_links').select('*').eq('item_id', itemId).order('created_at', { ascending: true }),
      neon.from('item_links').select('*').eq('linked_item_id', itemId).order('created_at', { ascending: true }),
    ])
    if (a.error) throw a.error
    if (b.error) throw b.error
    const rows = [...(a.data as LinkRow[]), ...(b.data as LinkRow[])]
    const seen = new Set<string>()
    return rows.map(fromLinkRow).filter((link) => (seen.has(link.id) ? false : (seen.add(link.id), true)))
  }

  async function fetchDocumentsForItem(itemId: string): Promise<ItemDocument[]> {
    const { data, error } = await neon.from('item_documents').select('*').eq('item_id', itemId).order('created_at', { ascending: true })
    if (error) throw error
    return (data as DocumentRow[]).map(fromDocumentRow)
  }

  return { items, wishlistItems, fetchItems, fetchWishlistItems, fetchLinksForItem, fetchDocumentsForItem, otherItemId }
}
```

- [ ] **Step 1: Write the settings composable**

```ts
// app/composables/useShareSettings.ts
export function useShareSettings() {
  const neon = useNeon()
  const shareEnabled = useState<boolean>('share-settings:enabled', () => false)
  const loaded = useState<boolean>('share-settings:loaded', () => false)

  async function fetchSettings() {
    const { data, error } = await neon.from('user_settings').select('*').maybeSingle()
    if (error) throw error
    shareEnabled.value = (data as { share_enabled: boolean } | null)?.share_enabled ?? false
    loaded.value = true
  }

  async function setShareEnabled(next: boolean) {
    const { data: existing, error: selectError } = await neon.from('user_settings').select('user_id').maybeSingle()
    if (selectError) throw selectError
    if (existing) {
      const { error } = await neon.from('user_settings').update({ share_enabled: next }).eq('user_id', (existing as { user_id: string }).user_id)
      if (error) throw error
    } else {
      const { error } = await neon.from('user_settings').insert({ share_enabled: next })
      if (error) throw error
    }
    shareEnabled.value = next
  }

  return { shareEnabled, loaded, fetchSettings, setShareEnabled }
}
```

**Steps:**

- [ ] **Step 1: Write the host-rewrite middleware**

```ts
// app/middleware/share-host.global.ts
export default defineNuxtRouteMiddleware((to) => {
  if (typeof window === 'undefined') return
  if (!window.location.hostname.startsWith('share.')) return
  if (to.path.startsWith('/share/')) return
  return navigateTo(`/share${to.path}`, { replace: true })
})
```

- [ ] **Step 2: Update the auth middleware to bypass share paths and the share host**

```ts
// app/middleware/auth.global.ts
export default defineNuxtRouteMiddleware(async (to) => {
  if (to.path.startsWith('/auth')) return
  if (to.path.startsWith('/share')) return
  if (typeof window !== 'undefined' && window.location.hostname.startsWith('share.')) return
  const { user, refreshSession } = useAuth()
  if (!user.value) await refreshSession()
  if (!user.value) return navigateTo('/auth/sign-in')
})
```

The hostname check is independent of the `to.path` check on purpose: Nuxt runs global middleware files in alphabetical order by default (`auth.global.ts` before `share-host.global.ts`), so on first load of `share.corvettepositraction.com/<uuid>`, `auth` would see the *unrewritten* path (`/<uuid>`, not yet `/share/<uuid>`) if it only checked `to.path`. Checking the hostname directly makes the bypass correct regardless of middleware ordering.

```vue
  try {
    await fetchItems()

    console.warn('Failed to load shared item:', err)
  }

  try {
    links.value = await fetchLinksForItem(item.value.id)
  } catch (err) {
    console.warn('Failed to load linked entries:', err)
  }
  try {
    documents.value = await fetchDocumentsForItem(item.value.id)
  } catch (err) {
    console.warn('Failed to load documents:', err)
  }
}

const linkedItems = computed(() => {
  if (!item.value) return [] as { linkId: string; item: Item }[]
  return links.value
    .map((l) => {
      const otherId = otherItemId(l, item.value!.id)
      const found = items.value.find((i) => i.id === otherId)
      return found ? { linkId: l.id, item: found } : null

  if (!item.value) return []

    const g = item.value.generation !== '—' ? GENERATIONS[item.value.generation as Exclude<Generation, '—'>] : undefined

    else display = raw != null && raw !== '' ? String(raw) : '—'
    out.push([f.label, display])
  }
  return out
})
```
